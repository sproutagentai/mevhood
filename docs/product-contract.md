# Completion contract — 2026-10-21

Mevy connects public verifiable evidence, frozen-control evolution, reviewed proposals and onchain digest receipts. The existing website/model and private searcher remain separate systems.

The operator needs a reproducible chain from real observations, through a bounded LLM proposal and explicit approval, to a new immutable forward experiment and prepared onchain receipts. An observer must be able to check where the evidence ends. No token, payout or arbitrary self-editing is added.

- Add proposal-to-next-experiment lineage, exact approval, stale-parent detection, full training cutoff, unchanged control/acceptance and unknown-cost handling.

## Acceptance before edits

1. Existing real evidence replays at the unchanged engine hash; seven-day/1,000-observation/gap/cost gates stay intact.
2. Proposal → exact approved draft → new experiment persists across restart and refuses renamed-only policies, invented blocks, stale/tampered approvals and training overlap.
3. Registry calldata decodes to exact IDs/digests; wrong chain/recorder/commitment, prior data and premature results fail closed. Creation calldata uses reviewed compiled artifacts and fixed constructor parameters.
4. Type checks, agent build, state/economic/handoff tests, local contracts and pinned real-router fork pass. Separate synthetic handoff, real source read, public deployment and paid model call.
5. Public changes stay under sproutagentai and match the file allowlist. No secret/private-engine data or unsupported runtime/deployment/model claim is published.

## External gates

Public deployment requires an explicitly selected recorder/controller, signer simulation and fee approval. They are not configured. A model credential/budget and continuous collection also require scoped runtime provisioning. Implementation, local/fork verification, public source and live operation are distinct acceptance states.
