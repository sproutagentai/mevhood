# Contributing

Open a focused change with its hypothesis, affected boundary and reproducible validation. Preserve the seven-day gate, report unsuccessful candidates, and do not turn a paper sample into a profitability claim.

Run `npm run verify`, `forge test -vv` and the committed bundle replay. The live source audit and pinned fork need network access and are separate from offline CI. If an engine source file changes, start a new experiment and produce a new evidence bundle; do not rewrite a frozen commitment to make old data appear forward.

Research policy proposals are bounded data, not code execution. New strategy families, external integrations, signing paths or public endpoints need an explicit design/security review and meaningful failure tests. Never place credentials, local state, private engine source, invoices with private details, or machine paths in a contribution.
